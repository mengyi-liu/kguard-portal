KGuardAgent · 安全算法中心

内容安全模型生产全流程
自动化智能体框架

从数据生产到模型训练、评估、压测、部署，KGuardAgent 以五个专注领域的 Agent 驱动算法流水线全自动运行。基于渐进式披露原则设计，每一层从基础到专业渐次展开，降低认知成本，聚焦核心决策。

Agent 层 决策 · 状态 · 调度 ▾
5 个专注领域的 ReAct Agent：DataAgent → TrainAgent → EvalAgent → PerfAgent → DeployAgent，共享 PipelineState，驱动模型生产全流程。每个 Agent 拥有独立工作边界，通过标准接口互传血缘节点。
Skill 层 SOP · 知识 · 判断规则 ▾
无状态知识文档，告诉 Agent「如何判断、如何决策」。严格三级渐进：基础版（产品经理维护，最低认知成本）→ 标准版（算法工程师维护）→ 专业版（资深算法+合规，高风险场景）。每个 Agent 各 3 个 Skill，不随意扩增。
Tool 层 原子执行 · Schema 约束 ▾
原子能力单元，可被 Agent 独立调用。严格 Schema 约束：tool(param: type) → ToolResult[T]。15+ 个核心 Tool，覆盖数据查询、模型训练、推理评估、压测、审批发布全链路。
Plugin 层 增值 · 热插拔 · 高级模式 ▾
灵活可插拔组件，保持系统迭代灵活度的 trade-off 设计。生命周期：experimental → stable → deprecated。标准接口：on_activate / get_tools / get_skills。各方团队均可自助提交。
渐进式披露设计原则：点击任意层展开详细信息。架构从上到下，复杂度逐层递增，使用者只需关注自己所在层——普通用户从基础 Skill 开始，高级开发者深入 Tool 和 Plugin。

Harness 工程设计

算法流水线的
自动化测试框架

KGuardAgent 的工程内核——Harness 框架定义了模型生产流水线的标准化接入规范，让每个环节可测试、可追溯、可复现。

01
PipelineState 中央状态
所有 Agent 共享一个不可变状态对象，数据血缘节点（DataSetVersion → ModelVersion → EvalResult → PerfReport → DeployRecord）全程可追溯，写入即持久化。
02
ReAct Loop 执行模型
每个 Agent 基于 Reason-Act-Observe 循环，Skill 提供判断规则，Tool 执行原子动作，循环直到达到终态或触发人审节点。
03
Schema 协议约束
所有 Tool 严格遵循函数签名规范，所有 Plugin 遵循标准接口协议。非必要不新增实体，新增必须重新评审，防止架构熵增。
04
人审节点设计
关键决策点（红线类目、资源超限、BLOCK 结论）自动暂停流程，通过 Kim Bot 消息路由到责任人，审批完成后自动恢复。
05
反馈环路
EvalAgent 输出 ITERATE_DATA 时自动回流触发 DataAgent，PerfAgent 输出 OPTIMIZE 时通知推理平台工程师，形成闭环迭代。
06
AuditEvent 审计链
从数据生产到模型上线，每个关键操作写入 AuditEvent（不可删除），合规审计、追溯分析均有完整链路支撑。
主链路 · 数据血缘传递方向
DataAgent → TrainAgent → EvalAgent → PerfAgent → DeployAgent
↩ ITERATE_DATA — EvalAgent 判定不通过时回流至 DataAgent

Agent 层

五个专注领域的
智能决策单元

每个 Agent 负责模型生产流水线中的一个专注阶段，通过标准 PipelineState 接口互传血缘节点，独立决策、协同驱动。

01
DataAgent
数据生产专家
→

采样策略制定、训练/测试集构建、数据质量门控（Quality Gate）。支持冷启动固定采样与主动学习难例挖掘。

输入 raw_source_spec
→
输出 DataSetVersion
分层采样 增量去重 质量 Check 合规清洗
02
TrainAgent
训练管理专家
→

超参配置、Alpina 任务提交、训练进度监控、最优 checkpoint 选取。支持单卡/多卡分布式与 RLHF/DPO 微调。

输入 DataSetVersion
→
输出 ModelVersion
超参搜索 断点续训 早停机制 RLHF/DPO
03
EvalAgent
评估引擎专家
→

离线批量推理、多阈值 ROC 分析、场景细分准召、回归 case 追踪。红线类目强制通过率 ≥0.999，输出四分类结论。

输入 ModelVersion
→
输出 EvalResult
多场景准召 ROC 分析 回归追踪 红线合规
04
PerfAgent
性能压测专家
→

系统级性能验收——算法合格之后、上线之前。多并发梯度压测、显卡数量预估、稳定性窗口验证，输出 PROCEED / OPTIMIZE / BLOCK 三种结论。

输入 EvalResult(DEPLOY)
→
输出 PerfReport
并发梯度 GPU 预估 SLA 保障 混沌测试
05
DeployAgent
部署管理专家
✓

多场景 Gate 检查、BPM 人工审批、灰度梯度发布（5%→20%→100%），全程 AuditEvent 留存。在线指标异常自动触发回滚。

输入 PerfReport(PROCEED)
→
输出 DeployRecord
Gate 检查 灰度发布 BPM 审批

Skill 层

渐进式披露的
三级工作流程

Skill 是无状态的知识文档，告诉 Agent「如何判断、如何决策」。三级严格分层，先剪枝到基础版，降低认知成本；需要时再展开标准版和专业版。

基础版
冷启动 · 极简 SOP
固定参数、最低门槛、全自动。产品经理可维护。先交付大图 + 评审，季度级迭代。
🔵 AI 产品经理
▶
升级触发
（复杂场景）
标准版
完整规程 · 异常分支
配置化参数、异常重试、多维检查。算法工程师维护。交付代码架构 + 评审，双周级迭代。
🟣 应用算法工程师
▶
升级触发
（合规高风险）
专业版
高风险 · 合规约束
红线规则、审计日志、人工抽检。资深算法+合规团队维护。随规则变动，评审后更新。
⚫ 资深算法 + 合规
基础版
data-sampling/base
  • 固定采样比例 10%，随机种子 42
  • Quality Gate：text_length ≥ 5 且 label != null
  • 直接写入 DataSetVersion，无异常分支
SourceSpec → DataSetVersion(draft)
标准版
data-sampling/standard
  • 分层采样（正/负/边界 = 6:3:1），配置化
  • 增量去重（MinHash LSH, jaccard=0.9）
  • 多维质量 check，不达标自动补采（最多重试 3 次）
SourceSpec + SamplingConfig → DataSetVersion(valid)
专业版
data-sampling/expert
  • 主动学习难例挖掘（模型不确定度排序）
  • 标注一致性阈值检查（Kappa ≥ 0.8）
  • 合规敏感类目清洗 + 审计日志（每条溯源）
SourceSpec + CompliancePolicy → DataSetVersion(certified)
基础版
train-config/base
  • 固定超参：lr=1e-4, epoch=3, batch=32
  • 单机单卡 A100，Kim Bot 触发 Alpina
  • 轮询等待（10min/次，超时 8h 告警）
DataSetVersion → ModelVersion(pending)
标准版
train-config/standard
  • 超参搜索空间（lr/batch/wd），Grid/Random
  • 多卡 DDP，early_stop(patience=3) + checkpoint
  • 自动选最优 checkpoint（按 val_loss）
DataSetVersion + HpSpace → ModelVersion(best)
专业版
train-config/expert
  • RLHF/DPO 微调：SFT → Reward → PPO/DPO
  • 课程学习策略 + 灾备自动迁移
  • 模型合规证书挂载到 ModelVersion
DataSetVersion + TrainStrategy → ModelVersion(rlhf)
基础版
eval-benchmark/base
  • 固定测试集，P/R/F1（threshold=0.5）
  • 通过条件：F1 ≥ 0.85 且 Recall ≥ 0.90
  • 直接输出 DEPLOY 或 ITERATE
ModelVersion → EvalResult(pass/fail)
标准版
eval-benchmark/standard
  • 多阈值 ROC，自动建议最优 threshold
  • 场景细分准召（泛色情/暴恐/广告/政治）
  • 回归 case 对比，回归率 >10% → ITERATE
ModelVersion + EvalConfig → EvalResult(scored)
专业版
eval-benchmark/expert
  • 红线类目通过率 ≥ 0.999，强制 BLOCK
  • 标注一致性（Kappa ≥ 0.85）
  • 合规审计报告自动生成，含测试集 hash
ModelVersion + ComplianceSpec → EvalResult + AuditLog
基础版
perf-benchmark/base
  • 固定并发=10，持续 5min
  • 通过条件：P99 < 2000ms & error_rate < 1%
  • 通过即 PROCEED，GPU 用默认值
ModelVersion → PerfReport(pass/fail)
标准版
perf-benchmark/standard
  • 并发梯度 5/20/50/100，延迟曲线分析
  • gpu_estimate(qps_target, mem_per_req_gb)
  • 稳定性窗口 15min，无 OOM / 内存泄漏
ModelVersion + LoadSpec → PerfReport(scored)
专业版
perf-benchmark/expert
  • SLA 协议级（P99/P999 分级），历史基线对比
  • 异常恢复规则：连续 3 次超阈值 → BLOCK
  • 回滚决策规则，上线后在线指标监控
ModelVersion + SLASpec → PerfReport + StabilityAudit
基础版
deploy-gate/base
  • Gate：eval=DEPLOY & perf=PROCEED
  • 直接灰度发布，初始比例 5%
  • Kim 消息通知相关人员
EvalResult + PerfReport → DeployRecord(5%)
标准版
deploy-gate/standard
  • 多场景 Gate 阈值（各类目独立配置）
  • 灰度梯度 5%→20%→100%，每级观察 24h
  • 在线指标异常自动回滚
EvalResult + PerfReport + GateConfig → DeployRecord(full)
专业版
deploy-gate/expert
  • 红线类目强制 BPM 人工审批，安全团队签字
  • 回滚触发：误报率 ΔΔ>5% 或 P99 ΔΔ>20%
  • AuditEvent 不可删除
EvalResult + SecurityGate → DeployRecord + AuditEvent

Tool 层

底层原子能力，
独立可调用

Tool 是最小执行单元。严格 Schema 约束，可被 Agent 直接调用，也可被 Plugin 组合复用。非必要不新增，新增必须评审。

Schema 设计原则
  • 签名tool(param: type) → ToolResult[T]
  • 返回统一 ToolResult 包装，含 status / data / error_msg
  • 幂等读操作天然幂等，写操作需 idempotency_key
  • 超时每个 Tool 声明 timeout_sec，Agent 据此规划重试
  • 原则非必要不新增实体，新增必须重新评审
Tool 名称 函数签名（简） 返回类型 归属 Agent 负责角色

alpina_submit_job (config: TrainConfig, ds_ver) ToolResult[JobId] TrainAgent 🔷 训练平台工程师

metric_compute (pred, threshold, category_field) ToolResult[MetricReport] EvalAgent 🔶 算法引擎工程师

audit_event_write (event: AuditEvent) ToolResult[AuditReceipt] DeployAgent 🔷 系统工程师

Plugin 层

灵活可插拔，
高级开发者模式

Plugin 是保持系统迭代灵活度的 trade-off 设计。各方团队可将增值功能做成插件，只需遵循标准接口协议，无需修改核心框架。

experimental → stable → deprecated
标准接口协议 · 所有 Plugin 必须实现
class BasePlugin:
    def on_activate(self, ctx: PipelineState) -> None:
        # 接收当前流水线状态，完成初始化
    
    def get_tools(self) -> List[ToolDef]:
        # 返回本 Plugin 提供的额外 Tool 列表
    
    def get_skills(self) -> List[SkillRef]:
        # 返回本 Plugin 注入的额外 Skill 引用
